# 论文 → HTML

交付可用浏览器直接打开的单个 HTML。以随附模板为准，桌面左侧上英文下中文，右侧是同一段的精读笔记。浅暖白底、浅青笔记、淡金高亮、章节目录和窄屏堆叠布局沿用模板。普通摘要或论文问答仍直接作答。

## 工作流程

1. **确定来源与范围。** 优先读用户提供的 PDF 或原文。明确指定文件时直接做。仅在同名候选无法区分时询问。默认单篇全文，包含摘要、正文、图表标题、附录与声明；参考文献保留原始条目。按用户指定的输出路径交付；研究目录已有 `shelf/` 时默认写入该目录。阅读材料与中间文件留在各自位置，临时数据放在系统临时目录。
2. **复原原文。** 查清物理页数、章节树、图表与公式的位置。优先用可靠的结构化原文交叉核对，再检查 PDF 实际排版。双栏按栏复原，跨栏或跨页续段要拼接，原段与列举项保留独立单元。区分标题、段落、图注、表格、页眉页脚和参考文献。处理排版断词、连字、脚注、特殊符号与引用，保留原意与原版内容。扫描页先 OCR 再对照图片核验。无法辨认的原文如实标明缺口。
3. **逐段写译文和笔记。** 按章节分批整理，再合并成一个数据文件。译文保留技术条件、数字、单位、适用范围、公式、引用与限制。建立小型术语表，跨章节保持术语一致。笔记用一到三条短句提炼机制、输入输出、适用条件或局限。并列分类可用三条列表。重点优先追踪作者的主张或证据；把额外理解明确标成阅读提示。每段可选双方各零到三个短语做淡金高亮。
4. **整理图表和公式。** 使用原图或截图，完整裁切，配双语图注和读图提示。表格保留行列、数值、单位和必要表注，提供可选中的中文表格和可展开的原表。复杂公式优先复用原版裁图，明确符号含义和对应页码；简单公式可用 Unicode。保留 DOI、原文出处与可核实的许可信息。章节、图、表的页内链接使用稳定 ID。
5. **生成并检查。** 阅读 [数据与命令](references/format.md)，用 `scripts/render.py` 生成成品，避免为每篇论文另写页面。逐节核对覆盖范围、原文顺序、引用与非空的译文/笔记，检查图表完整。可用浏览器时实际验证桌面与手机宽度、章节跳转及两个切换按钮。只交付 HTML，并报告缺页、识别异常或未实测的项目。

提取工具是可选的。使用 `scripts/pdf_source.py` 查看带坐标的原始文字块及裁切 PDF 图表；它不替你判断阅读顺序，也不翻译。优先使用现有 PyMuPDF 环境。翻译由当前 AI 在任务中完成，无需外部翻译服务。
